# InfiniFlow: ns-3 Simulation Code

This repository contains the ns-3 simulation implementation used to
evaluate **InfiniFlow**.

The codebase is organized under the `ns-3/simulator/` directory.
Each subdirectory contains an independent ns-3 instance configured
to evaluate specific congestion control or flow control mechanisms.

The general naming format is ns-3-xxx, 
where `xxx` indicates the protocol or algorithm being evaluated.

---
## 1. Repository Structure
### Simulator Directory Structure

The following implementations are included in the artifact.

### InfiniFlow

- **ns-3-infiniflow-mmf**

  Implementation of **InfiniFlow**, the proposed design in our paper.
  The scheduling policy follows Rounding Robin to achieve **Max-Min Fairness (MMF)**.

### Baseline Flow Control Mechanisms

- **ns-3-dt**

  Implementation using the **Dynamic Threshold (DT)** buffer management
  and credit-based flow control mechanism.

- **ns-3-infiniband**

  Implementation of **InfiniBand Credit-Based Flow Control (CBFC)**,
  representing the traditional credit-based link-level flow control
  used in InfiniBand networks.

- **ns-3-roce**

  Implementation of **RoCE-style Priority Flow Control (PFC)**.
  This configuration can be combined with datacenter congestion
  control algorithms such as **DCQCN** and **HPCC**.

- **ns-3-xpass**

  Implementation of the **ExpressPass** congestion control protocol.

- **ns-3-bfc**

  Implementation of the **BFC** in NSDI 2022.

### Ablation Study Variants

InfiniFlow consists of three core mechanisms:

- **UABD**
- **BUCP**
- **BUCP locking mechanism**

To analyze the contribution of each component, we provide two
ablation-study implementations:

- **ns-3-infiniflow-notap**

  Implements **UABD + BUCP without the locking mechanism**.

- **ns-3-infiniflow-nothreshold**

  Implements **UABD only**, without BUCP and without the locking
  mechanism.

These variants correspond to the ablation experiments presented
in the paper and allow reproducing the comparison between partial
and full InfiniFlow designs.

### Other Directories

In addition to the simulator implementations, the repository contains
several directories used for experiment execution and result analysis.

- **result**

  Stores experiment outputs and generated figures.

  - `data/`  
    Contains the raw **ns-3 simulation results** and CSV files.

  - `fpga-data/`  
    Contains **FPGA experiment results** used for comparison with the
    simulation results.

  - `graph/`  
    Stores the **figures generated by Python scripts**, corresponding
    to the plots used in the paper.

- **py-script**

  Contains **Python scripts used for data analysis and figure generation**.
  The first number in each script filename corresponds to the **figure
  number in the paper**.

- **sh-script**

  Contains the **top-level shell scripts used to run ns-3 experiments**
  for the evaluation presented in the paper.

## 2. Environment Requirements

### Software

- Linux environment (Ubuntu 22.04 is recommended)
- GCC / G++ with C++17 support
- CMake and Ninja (required by ns-3.39)
- Python 3 (for result processing and plotting)

---

## 3. Build and Configure ns-3

After cloning the repository, navigate to the ns-3 root directory:

```bash
cd ${PATH_TO_INFINIFLOW_FOLDER}/ns-3
```

make the build script executable：
```bash
chmod +x configure.sh
```

Run the build script:

```bash
./configure.sh
```

## 4. Running InfiniFlow Example Experiment

All ns-3 experiments used in the paper can be executed through the
top-level scripts provided in the `${PATH_TO_INFINIFLOW_FOLDER}/ns-3/simulator/sh-script/` directory.

```bash
cd ${PATH_TO_INFINIFLOW_FOLDER}/ns-3/simulator/sh-script
```

Each script corresponds to a specific experiment used to produce a figure in the paper.
### Run Experiments
To run an experiment, execute the corresponding script:
```bash
./xx-xxx.sh
```

The raw simulation results are stored in `result/data/`

The first number in both the shell script name and the Python script name
corresponds to the figure number in the paper.

## 5. Output and Results

All experiment outputs and generated figures are stored in the `result/`
directory.

- `result/data/`  
  Raw **ns-3 simulation results** produced by the experiment scripts.

- `result/fpga-data/`  
  **FPGA experimental results** used for comparison with the simulation
  results.

- `result/graph/`  
  **Final figures generated by the Python analysis scripts**.  
  These figures correspond to the plots presented in the paper.

After running the experiments (`sh-script/`) and processing the data
using the Python scripts (`py-script/`), the reproduced figures will
appear in:

`result/graph/`

## Tips

- Some figures require running data processing scripts first (those with “get” in their names) to convert raw output into CSV format, and then running the plotting scripts.
- Because different experiment scripts share the same directory, each script must be run individually; running them simultaneously may cause errors.
- Some experiments may take a really long time to run. For example, Experiment 20 took approximately 72 hours to complete on our server.
